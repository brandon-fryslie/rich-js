Effects ​

An effect changes how a renderable's cells look over time: a highlight sweeping through text, a pulse that brightens and dims, a fade, a word that blinks. It is an animation: given what the whole element draws in a frame, it returns an Animation whose value at a time t in seconds is a function from each cell's look and where the cell is to the cell's new look. A look is the cell's colors as the screen shows them, fg and bg, and its text attributes, attributes — bold, dim, italic, underline and the rest, each on, off or unset as the cell's style has it:

typescript
import type { Animation, CellLook, Drawn, EffectCell } from "@promptctl/rich-js";

type EffectFrame = (look: CellLook, cell: EffectCell) => CellLook;
type Effect = (drawn: Drawn) => Animation<EffectFrame>;
Not run

This is a shape to implement, not a complete program.

Effected makes the animation and asks it for the frame at t once a frame, then calls that frame once for each cell, so whatever holds for the whole frame, such as where a band of light stands at t, is worked out once rather than once a cell. The animation's validUntil is when the frame next changes, and since the animation is made from what the element draws, a loop that holds every cell still on a sixteen-color terminal can say its frame never changes there. A loop that moves every frame is Animation.continuous:

typescript
import { Animation, CATPPUCCIN_MOCHA, ColorRgba, Console, Effected, RichText, type Effect } from "@promptctl/rich-js";

// The ink brightens toward white across one second, then starts again.
const brighten: Effect = () =>
  Animation.continuous((t) => (look) => {
    const w = t % 1;
    const toward = (c: number): number => Math.round(c + (255 - c) * w);
    return { ...look, fg: new ColorRgba(toward(look.fg.red), toward(look.fg.green), toward(look.fg.blue)) };
  });

const console = new Console({ terminal: CATPPUCCIN_MOCHA });
for (const t of [0, 0.5, 0.9]) {
  console.print(new Effected(new RichText("brightening", { style: "#5f87d7" }), brighten, { key: "brighten" }).at(t));
}

Ready-made effects ​

The library ships six, and one signal. Four loop for as long as they are drawn, and two run once:

EffectWhat it looks like
shimmersunlight moving across water: a soft band of light crosses the element, glittering where ripples cross
pulsea slow glow on an element, warming into the light and settling back, the way an indicator breathes
sparklefireflies: short glowing strokes, each a few cells long, flashing and gone
wheelthe color of daylight going round: every hue turns once a period, far too slowly to see moving
fadeInink blooming in water: patches of the element surface first and the rest follows
dissolveOutmist lifting: the element thins in drifting patches until nothing is left

Each takes a Curve: seconds (a loop's period, or a transition's duration), an ease, and a swing, how far the move goes at full strength. EFFECT_CURVES holds the curves each effect was tuned to by eye, at 30 frames a second and at one. They are slow on purpose. At one frame a second, no cell's color moves more than a barely noticeable step from one frame to the next, so the motion reads as drift rather than as ticks.

EFFECT_CATALOGUE makes each of them by its name in EFFECT_CURVES, all the same way, with the curve and the light it was tuned with. EFFECT_CATALOGUE.loops holds the four loops, each made into an Effect, and EFFECT_CATALOGUE.transitions holds fade and dissolve, each made into a Transition. Every entry takes the element it is for, as an EffectTarget: its z, which places it in the noise the effect is drawn from, so two elements given different values do not move in lockstep. How wide the element is, an effect reads off what it draws in each frame, so a shimmer crosses a padded, wrapped or confined element where it shows. An entry also takes an optional curve to use in place of the tuned one. To offer a choice of effects, list Object.keys(EFFECT_CATALOGUE.loops); LoopName is the type of that choice. An effect added to the library then appears in the list without any change to your code.

Here is a status line under a shimmer, drawn at three moments:

typescript
import { CATPPUCCIN_MOCHA, ColorSpec, EFFECT_CATALOGUE, Effected, RichText, Style } from "@promptctl/rich-js";

const theme = CATPPUCCIN_MOCHA;
const ink = theme.foregroundColor;
const words = "Thinking about how light should cross these words";
const line = new RichText(words, { style: Style.fromColor(ColorSpec.fromRgba(ink), ColorSpec.fromRgba(theme.backgroundColor)) });

const lit = EFFECT_CATALOGUE.loops.shimmer({ z: 0 });

for (const t of [0, 60, 100]) {
  console.print(new Effected(line, lit, { key: "status" }).at(t));
}

A loop lights the element's own colors ​

shimmer, pulse and sparkle return a Loop: what the light does to one color, and how strongly it acts on each cell at each moment. onColors turns a loop into an Effect on the colors the element sets itself, each at its own share of the light, and that is how the catalogue makes them. The terminal's own colors are left alone, even where one has the hex of a color the element sets. Call the functions yourself to light with another color than the catalogue's (EFFECT_LIGHTS); a shimmer made that way also takes how many columns its light reaches either side of its centre, which the catalogue's entry chooses for you. Or call them to light only some of the element's colors, passed by hex as a second argument: onColors(loop, new Set([fill.hex])).

The shares keep the words readable. Effected measures every ink and ground pair the element draws its words in, and hands that measurement to the effect as drawn. Each color gets the largest share at which every pair it appears in still reads at its resting contrast, or at WCAG AA (4.5:1) if it rested above that, in the colors the output's depth writes it in. Below truecolor that is the color Effected writes for the cell's glyph or ground slot, so the promise holds at 256 colors as it does in truecolor. At 16 colors a loop holds still, as What an effect cannot change says, so it takes no contrast away. A color with contrast to spare glows brightly; one with none barely moves. Settling the shares is costly, so make the effect once and draw it in every frame: a frame that draws the colors an earlier frame drew reuses that frame's shares.

wheel turns hue rather than lighting a color, so it takes no shares; it keeps the same promise another way. Each color turns at its own relative luminance, and WCAG contrast is a ratio of luminances, so a turn costs a pair no contrast; its chroma is kept where the gamut has it. Writing the turned color rounds it, to 8 bits in truecolor and to a color the depth has an index for at 256, and the rounding is held to the light's floor: a color is written as whichever looks nearest its turn of the color it rested at and those whose luminance keeps every pair of words it is drawn in at its resting contrast, or at AA if it rested above that. A color drawn between a lighter color and a darker one, with less than about 3% of contrast to spare between them, has no room for that rounding at every hue, so it holds still rather than snap between its turn and its rest. It reads which colors are the element's, and which of them are fills, from the same measurement, and the element's segments from the cells it draws: a segment is a region of adjacent cells, beside or above one another, of one of the element's colors, each cell carrying it as its ground or, on the terminal's ground, as its ink, a blank carrying that ink included, so a panel's ground is one segment whatever lies on it, a paragraph is one, and a caption in a bar's color written under the bar turns with it. Each paces by where it sits — its centre row and its centre column from the element's left edge — so two segments of one fill at two places drift apart, a segment's neighbours pace a little apart from it and one a screen away paces on its own. Each color of a seam a separator drew turns with the segment of that color beside it, so a powerline cap keeps the color of the cell it caps, and a segment that grows by a column moves its hue a little, and those it pushes along by a column theirs as little.

What a frame knows ​

drawn is the same for every cell of a frame.

  • all() lists every cell the element draws, shown or not, each with its row, col and anchor, the columns its glyph takes (width), its ink and ground as the screen shows them (pair), and whether a strip's joiner drew it (seam), in the order the element draws them and listed before any cell is handed. A blank cell on the terminal's ground is in it: its ink, unseen, is the ink of the words beside it, so wheel reads a styled sentence as one run across its spaces. A strip's seam painted from the items beside it is listed but never handed its own look, since it follows them (One element of many). Under confined it is only the cells the owners drew.
  • cells() is those of all() the element shows something in, a glyph, a ground other than the terminal's or a line its style draws. A blank cell on the terminal's ground that draws no line is handed to the effect, but not in it. A transition uses it to spread its order over the cells that can be seen to move.

The rest describes the cells the element draws words in: those whose glyph is not blank and that a strip's joiner did not draw, since a powerline seam's ink is the fill beside it, not words.

  • pairs is every distinct ink and ground of those cells as the screen shows them, each with the terminal flags a cell carries and reverse, whether its style writes the ink in the ground's slot.
  • colors is the colors the element sets itself in those cells, by hex. fills is those of them that are a cell's ground.
  • depth and terminal are what the frame is written at and drawn on.

drawnOf(segments, depth, terminal) takes the same measurement of any rendered output, on the terminal the depth assumes where terminal is absent, as a frame is. Measure an element under an effect to read the contrast its words are left at.

One element of many ​

confined(effect, ...owners) applies effect only to the colors any of owners drew, and leaves every other color exactly as it was. It goes by who drew each cell, not by its color, so it can single out one of several items that share a fill. An owner is whatever stamps the cells it draws (Segment.anchorLines): every widget, every Viewport, and every item of a Strip or FlexStrip, however the strip wraps. Confined to anything that draws without stamping, such as the Strip itself, an effect moves nothing.

A strip's seams follow its items. A cell a CellSeparator paints from the items beside it is no item's, so no effect is handed it; once the effect has painted the items, each such cell is drawn again from the item cells beside it, the way its joiner drew it. A cell painted from a style name alone, such as plain's separator or metro's rail, follows no item: an effect paints it as it paints any cell, and one confined to the items leaves it as drawn, since no item drew it. Where the frame does not show a neighbour, as when a narrower container cuts the strip short, the effect is handed that neighbour's edge at the seam's own cell, so an effect over the whole element moves it with everything else, and one confined to the items leaves it as drawn. A powerline arrow keeps the fill it points out of as its ink and the fill it points into as its ground, wherever the effect took them:

typescript
import { EFFECT_CURVES, EFFECT_LIGHTS, Effected, SEPARATOR_STYLES, RichText, Strip, Style, confined, onColors, pulse } from "@promptctl/rich-js";

const fill = Style.parse("#1e1e2e on #89b4fa");
const items = ["main", "ctx 61%", "ok"].map((label) => new RichText(` ${label} `, { style: fill, end: "", noWrap: true }));
const strip = new Strip(items, SEPARATOR_STYLES.powerline);

// Only "ctx 61%" breathes, and the arrows either side of it follow; the other two items keep their fill.
const breathing = confined(onColors(pulse(EFFECT_CURVES.pulse, EFFECT_LIGHTS.sun, 0)), items[1]!);

for (const t of [0, 10, 20]) {
  console.print(new Effected(strip, breathing, { key: "status" }).at(t));
}

A color mixed from the two neighbours, such as the middle of a prism or a gradientSeam ramp, is mixed again from where the effect left them, so it moves with either. An effect that paints two neighbours one color leaves the seam between them lifted off that color, as a separator lifts any seam whose ink would vanish into its ground (Every seam shows). The same holds as a transition fades two neighbours into the terminal's ground: the seam between them is lifted off the color the effect draws that ground in. A gradientSeam ramp has no ink to lift, so under either it becomes that one color, as it is between any two alike backgrounds.

To move every item but one, name all the others in one call: confined(onColors(shimmer(…)), items[0]!, items[2]!) moves the colors either of them drew. One confined effect per item does not add up to that. confined nested in confined moves only the colors both owners drew, none for two separate items, and an Effected wrapped around another measures the inner one's output, so onColors settles different shares. The effect is handed only the cells one of its owners drew, so it costs one call a cell however many owners it has.

Several at once ​

layered(...effects) is one effect built from several, placed wherever an Effect goes, so Effected and confined take it unchanged. Each layer moves what the last one left, later layers on top, and when the frame next changes is when the soonest layer's does, so a composition of loops that hold still lets the host sleep.

typescript
import { EFFECT_CATALOGUE, Effected, RichText, Style, layered } from "@promptctl/rich-js";

const element = { z: 3 };
const bar = new RichText(" main  +3 ~2  opus ", { style: Style.parse("#1e1e2e on #89b4fa"), end: "", noWrap: true });

// Its hues turn, and a band of light crosses what the turn left.
const both = layered(EFFECT_CATALOGUE.loops.wheel(element), EFFECT_CATALOGUE.loops.shimmer(element));

for (const t of [0, 40, 80]) {
  console.print(new Effected(bar, both, { key: "bar" }).at(t));
}

A gradient or a steppedInk paints its ink over whatever is beneath it, so a light that should reach the letters goes after one.

Handing a list is the same call: layered(...chosen.map((name) => EFFECT_CATALOGUE.loops[name](element))) draws what one effect draws for a list of one and leaves the element as it is for none.

Every word reads at its floor, its resting contrast or WCAG AA whichever is lower, whatever the layers do and in whatever order. Each loop keeps that for the colors the element drew, and a color another layer moved is not one of those, so once the layers have moved a cell, its ground lands where the inks on it can still read and an ink that does not read slides to the luminance that does, on the side of the ground it stands on while that side has room. An ink a layer carries across its ground jumps the crossing, since nothing reads there: a light lifting a gradient's dark ink past a pale ground flips that word, and the same two effects on most palettes never come near it. A fill stays one fill whichever words are on it, and the floor outranks a color being the terminal's: a terminal ink is moved where its ground left it unreadable. None of this changes a byte for the catalogue's loops and attribute effects, or for a gradient or a steppedInk: one beside an effect that does nothing draws what it draws alone.

The floor holds for every layer, so veiled or a transition's effect stops at it inside layered, while done(t) says the transition has finished. Put a transition in an Effected around the one wearing the layers, which is where a lifecycle places it.

A transition says when it is done ​

fadeIn and dissolveOut return a Transition: the effect to draw, its schedule — an animation of when its frame next changes, whatever the element draws — and done(t), read off that schedule: true from the moment it never changes again, when every cell has arrived or gone, its curve's seconds after it began. The order is spread over the cells the element shows something in, so on any element, and under confined on one item of many, the first cell starts at 0 and the last settles at seconds. Each frame is worked out from the time and the cells it lists alone, so a seek, a reverse or a scrub draws a time exactly as playing up to it does, and one transition can be placed on any number of elements. An element that gains cells as it moves is spread over the order it has in each frame, so a new cell can move one already moving back toward where it began. A caller stops drawing an element that has dissolved, or drops the effect from one that has faded in, when done says so:

typescript
import { EFFECT_CATALOGUE } from "@promptctl/rich-js";

const leaving = EFFECT_CATALOGUE.transitions.dissolve({ z: 0 });
console.print([10, 29.9, 30].map((t) => `${t}s: ${leaving.done(t) ? "gone" : "leaving"}`).join(" · "));

Both blend toward the background of the terminal the frame is drawn on: the library never asks the terminal what that is.

A transition's frame changes every frame until it is done and never after: the animation its effect returns answers validUntil with t before done and Infinity from it, so a host drawing the element can stop waking for it without asking done itself.

The bytes can stop changing a little before done. Near its end, an ease that flattens out, such as the default ease-in-out, moves a cell by less than one step of a color channel, so nothing new is written. In truecolor that is within about a second on an element of several cells. An element of one cell takes the whole duration over its change, so its flat tail is longer. Below truecolor a color is written as the nearest one the depth has, and the last change lands when the curve passes halfway between the last two of them. That depends on the colors, and at 256 colors a fade can finish visibly several seconds early. done is when the curve ends, not when the bytes stop.

A signal steps ​

The loops are ambience, and nothing in them jumps. steppedInk is a signal, and jumps on purpose: every cell's ink steps through a sequence of colors on a step sequence, one color a step, looping, for the time it is handed, the way a gauge at its limit shows bright changing colors. Each step is a ColorStep, a color and its duration in seconds, and the durations are a StepSequence as frames are, so one sequence plays at one redraw a second and at sixty.

The ground stays as the cell draws it, and the words stay readable on it. Each step's ink is written as the color nearest the step's that the output's depth can draw and that reads on the cell's ground at the floor every loop here keeps: the cell's resting contrast, or WCAG AA if it rested above that, measured on the colors the terminal is sent. In truecolor that is the step itself, or its hue at the lightness nearest it that clears the floor. Below truecolor it is the nearest color the depth has an index for, so on a sixteen-color terminal the ink steps from slot to slot, where the loops hold still. The search runs once for each ink, ground and step, so every frame inside a step costs what any frame does, and the frame says it next changes when the step ends.

typescript
import { CATPPUCCIN_MOCHA, ColorRgba, Console, Effected, FrameSequence, Live, RichText, Style, steppedInk } from "@promptctl/rich-js";

const chevrons = new FrameSequence(["›", "››", "›››"].map((glyphs) => ({ text: new RichText(glyphs, { style: Style.parse("bold on #313244") }), seconds: 1 })));
const signal = steppedInk([
  { color: new ColorRgba(255, 85, 85), seconds: 1 },
  { color: new ColorRgba(241, 250, 140), seconds: 1 },
  { color: new ColorRgba(80, 250, 123), seconds: 1 },
]);

const console = new Console({ terminal: CATPPUCCIN_MOCHA });
const live = new Live(new Effected(chevrons, signal, { key: "effort" }), { console });
live.start();
try {
  await new Promise((resolve) => setTimeout(resolve, 6000));
} finally {
  live.stop();
}

A ramp across an element ​

gradient(ramp, colors?) lays a ColorRamp across the element: each lit cell's ink is the ramp's color at the cell's column, the leftmost cell reading the first stop and the rightmost the last. The ramp is an animation of a ramp, so ramp.moving(…) scrolls it along the element and turns its hues, and a still gradient is Animation.constant(ramp). The frame changes when the ramp does: every frame for a loop, never again once a tween settles it.

Lit cells are those whose ink is one of colors, named as a style names them and matched as the screen shows them at the output's depth, or by default every color the element sets itself. A named color must be opaque, and a misspelt or translucent one is refused when the gradient is made. Below truecolor, every ink that lands on the same palette color as a named one is lit with it. A terminal-supplied ink is never lit. Naming a rule's line color paints the line and leaves its title, and naming a panel's border color paints the border and leaves its body. A ramp color that would not read on the cell's ground is written as the nearest color that does, the same check steppedInk makes. On a sixteen-color terminal, or with no color, a gradient holds every cell as drawn, as the loops do.

typescript
import { Animation, ColorRamp, ColorRgba, EASES, Effected, Panel, WrapMode, RichText, gradient } from "@promptctl/rich-js";

const hues = new ColorRamp(EASES.linear, [
  { at: 0, color: new ColorRgba(255, 120, 100) },
  { at: 0.5, color: new ColorRgba(110, 190, 255) },
  { at: 1, color: new ColorRgba(255, 120, 100) },
]);
const flowing = gradient(hues.moving({ scroll: Animation.continuous(WrapMode.loop(4)) }), ["#a6e3a1"]);
const panel = new Panel(new RichText("the words keep their own color", { style: "#cdd6f4" }), { borderStyle: "#a6e3a1", width: 40 });

for (const t of [0, 1, 2]) {
  console.print(new Effected(panel, flowing, { key: "status" }).at(t));
}

Sampled on a step sequence ​

sampleAndHold(effect, stepSequence) samples any effect once a step: within a step it draws the frame at the step's start, and at each step's start it moves on. A wheel given a short curve and sampled once a second becomes a hue walk that turns a step at a time; sampled sixty times a second it still turns once a second, since the step sequence is seconds. At one redraw a second a step shorter than a second is skipped, as a frame is. The frame next changes at a step's start, the first one the sampled effect has moved by: an effect that moves every frame turns the sequence at the end of this step, one whose next step falls two steps on turns it there, and one that is done and says never leaves the sequence saying never.

sampleAndHold(transition, stepSequence) steps a transition the same way, its schedule with it: sampleAndHold(fadeIn(curve, 0), stepSequence([0.25])) fades in a quarter of a second at a time and is done at the first step that starts once the fade is, so an element arriving through it wakes its host on the quarters, not every frame.

typescript
import { EASES, EFFECT_CATALOGUE, Effected, RichText, Style, stepSequence, sampleAndHold } from "@promptctl/rich-js";

const label = new RichText(" rich-js ", { style: Style.parse("#1e1e2e on #89b4fa") });
const walk = sampleAndHold(EFFECT_CATALOGUE.loops.wheel({ z: 0 }, { seconds: 6, ease: EASES.linear, swing: 0 }), stepSequence([1]));

for (const t of [0, 0.5, 1, 2.5]) {
  console.print(new Effected(label, walk, { key: "brand" }).at(t));
}

An effect changes colors and attributes, never glyphs. To type, scramble or rain on what an element draws, use a glyph effect, which works the same way and nests with an effect over the same element.

An attribute on a step sequence ​

An effect moves a cell's attributes the way it moves its colors, by returning a look with them changed. blink is the one ready-made shape: given an attribute and two durations in seconds, off then on, it leaves every cell as drawn for off and sets the attribute for on, round and round. Off, its frame is the identity, so those frames are byte for byte what the element drew; it changes only when its step sequence does, so a host draws it twice a pass and rests between. ATTRIBUTE_DEFAULTS holds its two specs, and EFFECT_CATALOGUE.attributes makes them by name: blink, the words hidden (conceal) half of each second as a terminal's own blink does, and boldPulse, bold for the last three tenths of each second.

typescript
import { ColorDepth, DEFAULT_TERMINAL_THEME, EFFECT_CATALOGUE, Effected, RichText, renderToString } from "@promptctl/rich-js";

const pulsing = EFFECT_CATALOGUE.attributes.boldPulse({ z: 0 });
const word = new RichText("ready");

for (const t of [0, 0.69, 0.7, 0.99, 1]) {
  const drawn = renderToString(new Effected(word, pulsing, { key: "ready" }).at(t), { colorSystem: ColorDepth.TRUECOLOR, terminal: DEFAULT_TERMINAL_THEME });
  console.print(`t=${t}s  ${drawn.includes("\x1b[1m") ? "bold" : "as drawn"}`);
}

Writing an effect ​

Effected is any renderable under an effect over time: an animation whose value at t is the element with its cells' looks — colors and attributes — passed through the effect at that moment. Placed in a view, it draws at the frame's time and stamps its cells with exactly when the effect's frame next changes at the output's depth, so a loop that cannot move at sixteen colors lets the host sleep. Here it is drawn at one moment, .at(t):

typescript
import { Animation, ColorRgba, ColorRamp, EASES, Effected, WrapMode, RichText, type Effect } from "@promptctl/rich-js";

const highlight = new ColorRgba(255, 214, 102);
const sweep = WrapMode.loop(1.5);
const label = "  thinking about color  ";

const shimmer: Effect = () =>
  Animation.continuous((t) => {
    const centre = sweep(t) * label.length;
    return (look, cell) => {
      const weight = Math.max(0, 1 - Math.abs(cell.col - centre) / 4);
      const toward = new ColorRamp(EASES.linear, [
        { at: 0, color: look.fg },
        { at: 1, color: highlight },
      ]);
      return { ...look, fg: toward.at(weight) };
    };
  });

for (const t of [0, 0.5, 1]) {
  console.print(new Effected(new RichText(label), shimmer, { key: "thinking" }).at(t));
}

Time is an argument ​

Nothing in an effect reads a clock. Whoever draws frames builds the view for each frame's t, so the same t always draws the same output, at 30 frames a second or one every two seconds. How far along an effect is comes from the easing and phase vocabulary: ease(phase(t)).

What a cell knows ​

  • row and col count from the top-left of what the wrapped renderable drew, so a sweep crosses the element, not the screen. A wide glyph is one cell to the effect, at the column of its first half, and is never cut.
  • seed is a number in [0, 1) that stays the same for that cell on every frame, for effects that vary cell by cell. It is derived from the key option and the cell's position, so two elements showing the same text under different keys do not move in lockstep.
  • The look's fg and bg are what the screen shows: the glyph's color and the color behind it, so under reverse they are the style's two colors swapped. A cell that sets no color of its own, or names one of the sixteen ANSI colors, is handed that color from the terminal the frame is drawn on.
  • pair is the ink and ground the element drew the cell in, the shape drawn.pairs lists: what the cell is, where the look beside it is what is there now. Under one effect they are the same colors; under layered the look is what the layers beneath left, so a frame recognises a cell by its pair and moves its look. pair.terminal says, for each of the two as the screen shows them, whether that color is the terminal's own: one the style leaves unset or sets to default. Resolved through the terminal, it can have the same hex as a color the element wrote; terminal is what tells the two apart. onColors and wheel never move a color the terminal supplies. pair.reverse says whether the cell's style swaps its two slots, so the ink is written in the ground's slot.
  • The look's attributes are the cell's text attributes as its style sets them: each true, false or undefined, and an unset one lets a style laid beneath show through, as it does with no effect. reverse is not among them: whether the two colors are swapped is what decides which one the screen shows as ink, so an effect swaps them by moving the colors.
  • anchor is who drew the cell, and where it sits in their output, as Segment.anchorAt reads it off a frame, or undefined for a cell no owner stamped. confined reads it.
  • boxFrame is the drawing of a box the cell is the frame of (Box.frame), or undefined: an identity to compare, shared by the cells of one drawing and no other. marchingAnts reads it.

What an effect cannot change ​

An effect changes how cells look, never which cells exist or who drew them. Text, links, and the anchors that let a click or Tab reach a widget all pass through, so a button under an effect still takes clicks. A cell whose look comes back unchanged is drawn exactly as before: the identity effect, () => Animation.constant((look) => look), produces byte-identical output. Neighbouring cells of one segment that the terminal is sent alike stay one segment: below truecolor, two colors that land on one palette index are one run, and a cell moved too little for the depth to show keeps the color it was written in, none included. Cells from two segments stay two, as the wrapped renderable drew them.

With no color output at all, an effect has nothing to change, and the wrapped renderable draws as it would without it.

A color an effect moves is written as the nearest color the output's depth can draw on the frame's terminal: the RGB value itself in truecolor; otherwise the nearest of the terminal's default color, its sixteen and, at 256 colors, the cube and grey ramp. A translucent color is laid on what is beneath it first, as every translucent color the library writes is: the ground on black, since a terminal cannot say what lies under its cells, and the glyph on that ground. So below truecolor a color moved a little off an ANSI slot or the default color is still drawn as that one. On a sixteen-color terminal a move that does show is a jump to another slot, so there a loop — wheel, and any lit by onColors, every one in the catalogue among them — holds every cell still rather than flickering between slots. A transition still runs, from slot to slot, since it moves once and is done, and so does steppedInk, since stepping is what a signal is for.

layered is the way to run several effects on one element. Nesting is the other: new Effected(new Effected(child, a, options), b, options) draws each cell in the colors that applying a and then b gives it. The bytes can differ from one effect that calls a then b: the outer layer sees the inner layer's output as written, so a color the inner layer changed reaches the outer one already rounded to the output's depth, and stays written as that even where the outer one moves it back. The outer layer's drawn is measured on the inner layer's output too, so a loop lit by onColors on the outside settles its shares against colors that move every frame.
